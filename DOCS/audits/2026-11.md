# Audit, November 2026

Thirteen audits of 1.1.0, run 2026-11-15 to 2026-11-16: four on
malicious input, four comparing output with reference tools, two checking
the docs against behaviour, and two on code health. Each finding was
reproduced on the release binary before it was reported, and the top ones
were rerun once more by hand. The repo was not changed by the audits.

The full reports (with file:line, repro command and suggested fix for each
finding) and about 900 repro files (inputs and the scripts that made them) are kept outside the repo, in
`~/Developer/sublime-audit-2026-11/` (`reports/`, `repro/<audit>/`).

Critical means a crash, hang, or memory blowup from a small input, or
silently wrong data. Most of the 79 criticals are hostile-input failures
that fall into five root causes (below), so the fix count is far smaller
than the finding count.

## What held up

The codecs are accurate: 199 JPEG variants bit-exact against
libjpeg-turbo, WebP bit-exact against dwebp, every lossless image writer
exact through ImageMagick, HEIC within half a level of ffmpeg's planes.
DEFLATE survived 30,000 corrupted streams, the ZIP reader 35 lying-header
cases, Pages/Numbers about 10,000 reference and protobuf mutations, and
the HEVC decoder core 90,000 random bitstreams, all without a fault. No
external entity is ever fetched, nothing is written by a ZIP entry name,
and no `unsafe` exists outside the wasm FFI. TOML matches tomllib, CSV
matches Python's csv, docx/odt/rtf outputs open in LibreOffice and Pages
with their structure, and `FORMATS.md`/`CONVERSIONS.md` match the registry
byte for byte.

## Performance and memory

On large real files Sublime beat pandoc, LibreOffice, Python, jq, Miller,
ImageMagick and sips in every case tried, usually by 5 to 50 times, with
less memory; CSV, TSV, JSON and JSONL run at 150 to 420 MB/s in 2 to 3 MB
flat to 480 MB, from files and stdin. The exceptions, with measured
patches in `~/Developer/sublime-audit-2026-11/perf/patches.diff`:

| Where | What | Measured |
|---|---|---|
| Markdown read | Crash on ordinary text: a bare email address after non-ASCII text (`Zoë abcd x@example.com`) slices inside a character (`src/io/markdown/inline.rs:1751`, `:1754`); every Markdown conversion and CSV -> HTML | panic |
| PDF read | `inflate` sizes a zeroed slab at `min(limit, input * 1032)` with a 2 GB limit, so each small page stream gets 8 MB (`src/io/deflate/inflate.rs:1062`, `src/io/pdf/filter.rs:261`); half the run is page zeroing. The memory 2a could not explain | 1,390 pages: 202 to 23 MB, 1.58 to 1.09 s with a three-line patch |
| PDF write | One `BT … Tj ET` per word and per space, 17 bytes of content per character (`src/io/pdf/compose.rs:530`, `:576`); 2 to 3 MB/s | 36% faster with two small patches; one text object per line estimated 3 to 5 times smaller |
| JSON, JSONL -> CSV | One loss event kept per nested value (`src/converters/json_to_csv.rs:493`) | 470 MB file: 101 MB peak against about 3; 37,301 stderr lines |
| ODT write | Body held three extra times (`src/io/odt/writer.rs:38`) | 16 MB Markdown: 715 MB against Word output's 61 |
| Documents | The model costs 20 to 30 times the file on table-heavy Word, ODT, RTF, EPUB; Word lists and hyperlinks looked up by linear scan (`src/io/docx/reader.rs:1930`, `:438`) | 80,000 lists: 7.0 s, quadrupling per doubling |

## Hostile input: five root causes

1. **No depth limit.** Recursive readers and writers overflow the stack:
   JSON, YAML, TOML, XML, Markdown, HTML, DOCX and ODT nested tables,
   protobuf groups, RTF `\itap`, a self-referencing footnote, PDF
   reference cycles (`/Length`, object streams, Indexed color spaces), a
   HEIC grid that lists itself. Natively it takes 12,000 to 59,000 levels;
   in wasm 3,000 to 8,000 (6 KB of input), and one trap leaves the module
   broken for every later conversion (`wasm/sublime.js` never
   re-instantiates).
2. **Counts from the file used as sizes.** DOCX `gridSpan`, `ilvl`, chart
   `idx`; XLSX column refs, `<dimension>`, `row r`; ODS repeat products;
   ODT `text:s`; Pages table sizes; ZIP64 sizes into `with_capacity`; PDF
   `/N`, `/W`, predictor columns, image `/Width`; list start 4294967295;
   Numbers format widths into `format!` (panic). Images: PNG row buffers
   outside the size guard (69 bytes to 2 GB), progressive JPEG
   coefficients, the animated WebP canvas, TIFF strips, PBM to ICO, and
   32-bit wraps of `width * channels` in wasm.
3. **No total budget on produced bytes.** Flate, LZW, RunLength, ZIP and
   Snappy bombs; YAML aliases (350 bytes to 2 GB); HTML `colspan` filler;
   Markdown table padding (132 KB to 879 MB); content copied per reference
   (EPUB spine entries, DOCX headers per section, ODT tracked changes,
   footnote references, repeated PDF `/Contents`).
4. **Repeated work.** Quadratic or worse paths: PDF fonts reloaded per
   `Tf`, resources cloned per page, object streams cloned per lookup
   (also slows ordinary large PDFs), line-spacing tally; Markdown
   reference definitions, HTML nesting, XML attributes, RTF cells, unique
   sheet titles.
5. **Plain panics on malformed data.** PDF offsets past end of file (86 of
   3,400 random mutations, and one real pdf.js file); XML unterminated
   CDATA (crashes DOCX, XLSX, ODT, ODS, EPUB); EPUB empty cover `href`;
   WebP RIFF size under 4; HEVC conformance window larger than the
   picture; JPEG sampling factors and scan components; BMP all-ones mask;
   tiled TIFF under 8 bits; HEIC 64-bit box sizes; RTF lists past level 8.

## Proposed fix plan

1. **Silent wrong output**, the table above. Each has a repro; many are
   one to ten lines (2a C1 and the HTML comment are one line each).
2. **One limits module** (`src/limits.rs`, carried in the conversion
   context), as 7a and 7b both proposed:
   - `Depth`, checked at the nine recursion sites listed in 7a 2.3;
   - `Budget`, charged at `Document::push_text`, the writers' flush points,
     every decompressor, and `Tree::push`/`copy_subtree`;
   - a checked-count helper for XML attributes and Pages views;
   - a `Dimensions` type and a checked `RowSink` at the two places image
     readers get their sink (`src/converters/image.rs:203`, `:671`);
   - `Table::normalize` where each reader finishes a table.
   Then the plain panics one by one, and wasm re-instantiation after a
   trap.
3. **Regression corpus.** The repro inputs become `tests/fixtures/hostile/`
   with a subprocess test (each must end in a clean error or output within
   time and memory), large inputs made by Rust generators, and a
   `wasm/hostile.mjs` run of the same set in the wasm CI job.
4. **Docs.** 3a and 3b give replacement text for 35 + 19 claims, among
   them `docx.md` describing an older reader, `pdf.md` calling every
   image-to-PDF path lossless, the exit-code definition, `LANGUAGES.md`
   encodings, and stale status lists in png, tiff, xlsx, numbers, qoi,
   netpbm.
5. **Code health.** `rust-version = "1.85"` does not build (needs 1.88; add
   a CI job or raise it). Merge the duplicate helpers that disagree (three
   JPEG frame scanners, four media-type tables, two `data:` URI parsers, a
   second CRC-32); remove 13 dead items; split the 12,883-line Pages
   writer when it is next touched; give errors the file and object they
   are about.

Not covered by any audit: Excel- and Word-on-Windows files, scanned PDFs,
rendering in Acrobat or Word, real camera originals, browsers other than
node for wasm.
